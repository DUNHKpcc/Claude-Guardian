## 最终结论

**有本机实测通过的关键场景，但整张验收单未全部通过。**

- 已通过：实际目标路由走 TUN、停核心后阻止直连、T5 原生故障演练、真实重启后的关键开机保护检查，以及回滚、卸载和恢复。
- 未通过：PF 生效时换网后出现域名解析失败；UDP 采样不稳定，换网后未完成出口一致性验证。

测试结束后已撤销临时 PF，恢复原始 Disabled 状态，Guardian 规则为空；测试开机项、状态目录及令牌均不存在，主 PF 配置哈希与初始值一致。IP、域名、显式代理连接均恢复 HTTP 200，UDP 对照恢复通过。未修改代理配置、系统 DNS、系统时间、时区或客户端自启设置。

## 环境与证据范围

测试样本为 macOS 15.7.4、arm64、Clash Verge 2.5.8、mihomo v1.19.32，服务模式、gVisor TUN、VLESS 节点；严格路由和自动路由开启、核心 IPv6 关闭，使用 fake-ip 与 DNS 劫持。结果只代表这一组环境，不代表其他系统、客户端版本、节点或网卡均通过。

PF 操作和需要现场触发的睡眠、换网、重启由用户在本机终端执行。Agent 读取本机私有结果并作定向复核；浏览器结论及人工触发动作标明来源，未把人工报告当作自动验证。未启动 Claude Desktop，因此不覆盖该应用自身运行时的流量。

用户确认本次不以系统时间、时区作为验收标准；浏览器语言沿用测试单例外。排除时间/时区仅适用于本轮，不修改通用测试标准。验证真实重启仍要求启动时间变化及本次启动后的加载事件，不能用重新运行脚本代替。

公开报告只包含脱敏结论及必要环境版本。真实出口、节点、订阅、凭据、网络标识、个人路径、原始机器记录与临时执行器均不提交或打包。

## 检测限制与故障边界

- macOS 路由检测当前只查 `route -n get default`。TUN 使用更具体的路由时，默认路由仍可在物理网卡。人工复核使用 `route -n get 1.1.1.1`；本轮将有证据的 TUN 项标记通过，原生 fail/unknown 和完整判定器原值保留，未修产品代码。
- 测试用 Python 初次缺少系统 CA 信任。仅对测试进程设置 `SSL_CERT_FILE=/etc/ssl/cert.pem`，保留正常证书校验，没有修改全局证书库。
- 首次显式代理 curl 35 缺少同期 CONNECT/核心错误/包目标证据；随后带观测复测未复现，不能写成根因已查明或缺陷已修复。
- 本会话临时执行器曾在提前 resume 被拒绝后错误清理准备项，已修复并做隔离回归；随后重新准备并真正重启。临时执行器修复不计为项目产品修复，其测试不替代真机验收。
