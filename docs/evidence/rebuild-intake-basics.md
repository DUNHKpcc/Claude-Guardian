### T01: complete novice web-writing path

The scenario first distinguishes first subscription, returning after expiry and current subscriber. A current subscriber's actual purchase or nonpurchase task determines whether a target plan is relevant; the case does not justify asking irrelevant purchase questions simply to satisfy a test.

The local web-writing trace retains the supplied purpose and step-by-step preference. It checks the complete question objects and ordered applicable path: system/purpose/version, desired plan where applicable, registered/login self-report and relevant history, local default proposal and explicit acceptance, necessary network and selected web-payment prerequisites, local dependencies/protection and delivery preference. PC0 checkout facts that require real contact remain explicit deferred gaps; they are never silently passed.

The required short local/VM/VPS comparison is permitted. The negative condition is not a ban on the word “VPS”: after choosing local web writing, no unrelated server/VM resource survey, API billing or enterprise-opening branch is activated. Q-C07 remains retired in the actual registry and cannot be revived as an ownership question. A preference for beginner explanation does not create extra scripts or install actions.

### T02: complete expert summary, then only genuine gaps

One normalized full environment summary is supplied in a single batch. Each explicit fact retains its value, source, timestamp and proper account/device subject. Once all currently applicable facts are present, there is no repeated basic question. The expert explanation preference changes no authorization gate.

A later genuinely missing, stale or conflicting fact produces its scoped question, while unrelated complete facts remain unchanged. Reordered batches must not produce different derived task/subscription state. A malformed late answer or attempted permission field rejects the entire batch without partially updating the original state.

G1 coverage/G2 planning readiness do not open G3. Persistence remains separately controlled; plan acceptance, route selection, inferred expertise or a completed questionnaire cannot grant file saving, device reads, first contact, login or payment. The complete fixed IPv4-policy projection still reports enforcement/native acceptance unestablished; G2 is only planning readiness.

1. **SKILL “开始方式”, instruction 2:** existing facts are reused before gaps; the first missing normal business question distinguishes first, expired/returning and current subscription. It expressly says technical proficiency is not payment status and gives urgent incidents precedence. This matches both asking Q-J01 when unknown and skipping it when explicitly supplied.
2. **Intake “Scheduling”, normal-order sentence:** Q-J01 precedes OS/purpose/target plan, then account history/route and relevant network/payment/protection. The same paragraph says technical skill changes explanation depth only. Therefore L0 is not routed to infrastructure merely because the user needs simple explanations.
3. **Intake journey paragraph, first sentence:** the four journey values include unknown, and first/returning answers establish only a reported lack of current subscription. This does not claim a billing lookup or infer account registration/history.
4. **Intake journey paragraph, current-subscriber sentence:** Q-C11 is asked only if the current task is missing. This prevents a current subscriber from being mechanically sent back through new-purchase preparation.
5. **Intake journey paragraph, target-plan and legacy-billing sentences:** Q-C08 means desired plan, while old-plan/channel topics activate only for relevant existing billing or an actual contradiction. This preserves the original “目标套餐和相关前提” rather than substituting old entitlement investigation.
6. **SKILL “开始方式”, instruction 3:** local is a recommendation that requires acceptance; VM/VPS are independent alternatives, not a skill hierarchy, and owned equipment does not choose the route. It supports the short optional comparison and prohibits forced migration.
7. **Intake local-route paragraph:** `default_proposal` remains unaccepted until `explicit_choice`, `task_context` or `accepted_default`. The next paragraph preserves unknown/refusal/deferral as a proposal and conditional advice. Silence cannot stand in for acceptance.
8. **SKILL “开始方式”, instruction 4:** Q-C07 is permanently retired and cannot be restored under an ownership/control synonym. This is stronger than merely omitting its ID from one trace. Device and purchase permissions are handled elsewhere without recreating the removed question.
9. **Routes R-LOCAL scope sentence:** browser-only work does not require Code/Desktop or firewall setup. This is the relevant anti-overreach rule for the literal web-writing scenario; an unrelated advanced module being listed elsewhere is not a recommendation to execute it.
10. **Routes M01 final paragraph:** initial choice is short, local is the default recommendation, novice/expert explanation depth can differ, and safety gates do not change with skill. No server purchase or enterprise-registration recommendation follows from L0.
11. **Accounts M02 A1 item 5:** organization/seat/administrator/data-scope questions are conditional on an actual enterprise need, not a universal account-ownership survey. M03 B1 says to check existing payment tools rather than lead ordinary subscribers into account opening, new cards, investment or LLC creation; B4 makes API/organization material conditional and rejects copying historical vendor rankings as current recommendations. Product subscription, API balances and organization seats are not default substitutes.
12. **Accounts M03/PC0 handling and contact-policy phase contract:** only relevant payment categories and truthful prerequisite facts are collected before contact; live checkout/eligibility is deferred to its permitted phase. A missing real checkout fact is not filled by the synthetic test, nor does the evidence recommend spending money before it is verified.
13. **SKILL “按需加载” and start instruction 6:** content is loaded by the actual task and tools are used only within implemented capability and specific authority. These sentences prohibit interpreting the capability catalogue as a beginner checklist of every script.

### T02 clauses

1. **SKILL “开始方式”, instruction 2:** reuse supplied facts before asking gaps. The first missing business question is conditional on being missing; a fully supplied summary must not be forced through the opening again.
2. **Intake “Scheduling”, first paragraph, sentences 1–3:** read existing task facts, ask one decision per turn, absorb every useful fact in a reply and skip known/not-applicable items. This is the exact host-to-`record_facts` contract tested by one complete batch.
3. **Intake same paragraph, clarification sentence:** one focused clarification is followed by unknown/refusal/pause/limited-plan exits. A genuine gap can be queried without becoming repeated basic questioning or endless confirmation.
4. **Intake multi-fact/local-environment task paragraph:** one turn can absorb journey, current task, OS and route, while subscription evidence/source/time are preserved. Task labels are not permission or fabricated payment history. The candidate verifies those distinctions rather than equating “expert” with “paid”.
5. **Intake “Fact states and gates”, fact-envelope sentences:** value, state, source, target and observation time remain together; unknown/refused are not false and protected facts cannot be inferred. A supplied summary is still reported unless separately observed under an authorized mechanism.
6. **Intake G1 sentence:** coverage accounts for every applicable branch and visible unknowns. A complete summary can therefore finish without re-asking known questions, while an actual omitted prerequisite still remains a gap.
7. **Intake G2 sentence:** personalization needs enough current target/task/route/protection and relevant network/payment/resource facts. The test's “complete” refers to that chosen task, not universal native validation.
8. **Intake G3 sentence:** exact change/purchase, current prerequisites, scope/price, specific authorization, supported capability and recovery are still required. Approval cannot manufacture execution capability, and summary completeness cannot replace approval.
9. **Contact policy “Permissions and reporting”, first paragraph:** question answers, plan acceptance, host permission, OS privilege, first contact and payment are distinct. Silence/defaults/elapsed time grant none of the others. These sentences prevent the expert fast path from weakening action-time safeguards.
10. **Contact policy authorized-read paragraph:** actual reads still bind target, minimum fields, timeout and redaction; denied or unavailable capability does not authorize elevation. The tests' no-I/O sentinels exercise the pure intake boundary, not a native read approval bypass.
11. **SKILL independent-repair paragraph:** the Agent may investigate and propose scoped repair, but cannot provide its own True callback instead of user confirmation. This is consistent with blocked G3 and does not require unnecessary approval for ordinary explanations.
12. **SKILL protection/persistence sentences and intake persistence API contract:** save/export requires explicit scoped consent and no public state dump. An expert summary does not confer permission to save private facts merely because they are complete.
