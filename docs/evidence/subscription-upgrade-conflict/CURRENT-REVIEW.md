## Projection and limits

The projection uses exact fictional user/assistant text and lossless semantic API JSON. The separate public dialogue chain covers text only, not the original context containing private helper receipts. Original context/record hashes allow an authorized holder of the private originals to compare provenance; hashes alone do not prove execution, model identity, independence or access isolation. Full raw request serialization, source-read events, timestamps unrelated to API replay, executor paths, internal identities, registration records, coordination envelopes and private artifact handles are intentionally absent. Historical run counts are explicit summaries, not byte-identical exported logs. Every transformation is declared in `projection-map.json`.

- Blinding was instruction-scoped on a shared filesystem, not physical isolation; recorded helper calls were not an independently enforced complete access monitor
- Synthetic page/account reports are not live service observations. Conversational states stay PC0 without completed purchase or persistence consent. A separate fully covered synthetic CLI case uses a PC2 label solely to exercise blocking; it is not real contact authority
- Current-source compatibility is deterministic helper implementation evidence. Review verdicts are bounded human-readable assessments, not proof of unrestricted model behavior
- Linux execution, forced cp1252 I/O and Python 3.10 AST parsing are not native Python 3.10, macOS or Windows tests
- Prior whole-T01 and other-case acceptance is separate. Historical test counts do not become new T77/T80 model acceptance
- Runtime and Skill contents are unchanged. The project's explicit 63-member Skill inventory excludes this evidence
