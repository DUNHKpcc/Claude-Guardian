# 全范围实现与验收跟踪

更新：2026-10-15。基线：主规范 v0.1.10-draft、ENV-SPEC v0.3-draft；审阅起点 commit `60e7461eacec28d442e334633b2ff890eb865e3f`。本文件是工程跟踪，不是目标设备检测报告。

## 1. 范围与状态规则

用户最新要求是完成两份设计文档的全部范围，诊断预览只是中间交付。文档历史阶段的“只写 Spec／暂不编码”不再阻止当前实施；它们不应从来源快照中删除，也不代表已获得目标设备联网、系统修改、登录、付款或删除授权。用户愿意连接 Mac 验证，仍须先验证连接、绑定目标，再按实际操作取得授权。

- 全范围包括 M00—M14、ENV-01—10、三条独立路线、完整访谈条件分支、阶段交接、恢复和发行维护
- 全范围不等于所有操作一键化；教学、官方处理交接、本人完成的身份核验/支付、明确的人工平台分支也是规定产物，但必须给可用步骤、前提、验收和失败出口，不能只列标题
- 不加入原规范明确排除的身份轮换、账号循环、伪造资料、风控概率、整机默认禁 UDP/IPv6 等行为
- `design`、`code`、`automated_test`、`native_acceptance`、`operation_authorization` 五列独立。文档覆盖、测试函数存在、夹具通过、一次 Mac 实测均不能互相替代
- 全部 218 个原案例在附录逐项保留。此轮没有执行其正式逐案例验收，统一状态为“待建立证据”，不是统一宣称实现不存在
- 仓库 `docs/validation.md` 记载预览版 42 项 Linux 行为测试通过；这是既有记录，本轮未重新执行，也不继承历史契约包的 56 项结果。并行新增实现须按真实测试记录更新映射
- 版本支持须精确到产品/版本/安装方式/操作（audit/probe/plan/apply/verify/rollback），禁止总括 `supported=true`
- 并行开发提示：本表的“当前证据”是审阅起点的预览基线。编写期间已出现 `interview_flow.py`、`network_probes.py`、`transactions.py`、`tests/test_inventory.py` 等新文件；此轮未完成这些并行成果的代码/测试复核，不把它们计为已完成，也不应读成它们不存在。合并负责人须补入实际commit、测试与逐项覆盖；平台门槛继续独立。
